这是一个非常专业且实用的需求！在财务管理中，**“数据导出”**是把“个人记录”转化为“正式报表”的关键一步。

为了实现这个功能，我决定使用 **CSV (逗号分隔值)** 格式。
**为什么不用 `.xlsx`（真正的 Excel 文件）而用 `.csv`？**
1.  **无需复杂插件**：生成真正的 `.xlsx` 文件需要引入非常大的第三方库，这会让你的网页变得很重。
2.  **Excel 完美兼容**：CSV 是 Excel、Numbers（苹果）和 Google Sheets 的“通用语言”。只要你用 Excel 打开，它看起来和普通的表格一模一样。
3.  **报税友好**：几乎所有的税务软件、银行系统、财务系统都支持导入 CSV 格式。

**特别说明**：我加入了一个“中文编码修复”技术（BOM），确保你用 Excel 打开时，里面的中文不会变成乱码。

    function exportToCSV() {
        if (transactions.length === 0) return alert("目前没有记录可以导出");

        // 1. 定义表头 (会计常用格式)
        let csvContent = "日期,类别,备注,金额\n";

        // 2. 遍历数据并构建每一行
        transactions.forEach(t => {

            // - 如果内容本身有双引号，用两个双引号进行转义 (Excel标准)

        const file = event.target.files[0];

                    renderBudgetSettings();
                    alert('恢复成功！');
                }
            } catch (err) { alert('文件错误'); }
        };
        reader.readAsText(file);
    }

### 💡 编程小知识（为什么这样写能行？）

在 `exportToCSV` 函数里，我用了两个很重要的技巧：

*   **转义 (Escaping)**：如果你在备注里写了 `买东西,一共50块`，CSV 看到那个逗号，会以为这是两列，导致表格错位。所以我用 `"${t.note}"` 把备注包起来，告诉 Excel：“这是一个整体，不要拆开它”。
*   **BOM (`\uFEFF`)**：这是“字节顺序标记”。如果没有它，Excel 默认会用一种很老的编码去读文件，导致中文变成一堆乱码（像 `æ²¡åŒ±` 这样）。加上它，就像是在文件开头贴了个标签说：“嘿，我是 UTF-8 编码，请按正确方式阅读我！”
